# Chassis_2026 引脚分配

主控：STM32F103C8T6（LQFP48）

> **本表按 PCB 实际接线填写，是唯一的引脚依据。**
> 代码里的对应关系全部来自 `config/pin_config.h`，两者必须一致；
> 改完引脚后跑 `tests/check_pins.ps1` 检查有没有两个功能抢同一个脚。
>
> 已确认的硬件事实：
> - 电机：MG513 系列**霍尔编码器款**（MG513X / MG513XL 接口相同）
>   6 线定义：1=电机线一、2=编码器电源、3=编码器 A 相、4=编码器 B 相、
>             5=编码器地线、6=电机线+
> - 底盘：**后双轮差速驱动**（后轴两个驱动轮 + 前部万向轮）
> - **电机驱动模块：TB6612**，丝印
>   `PWMA AIN1 AIN2 STBY BIN1 BIN2 PWMB | E1A E1B E2A E2B | ADC 5V GND`
>   - A 通道（PWMA/AIN1/AIN2/E1A/E1B）= **左轮**；
>     B 通道（PWMB/BIN1/BIN2/E2A/E2B）= **右轮**；
>   - `STBY` 必须为高，否则整片待机、电机不转；
>   - `5V` 是模块逻辑供电，`GND` 与主控共地；
>   - `ADC` 是板上电流检测输出，**本工程不用**，悬空即可。

## 三处必须知道的约束

### 1）左轮编码器在 PA0/PA1 —— 已确认 3.3V 供电

PA0~PA7、PB0、PB1 是 **TTa 脚，不容忍 5V**。

- TIM2 的 CH1/CH2 默认就落在 PA0/PA1，编码器模式**只认 CH1/CH2**，
  所以这两根线上放别的功能就只能靠重映射，而重映射会把它们挪到 PA15/PB3
  （那两个脚现在归循迹 CH6/CH7）。
- **硬件已确认**：左轮编码器由 **3.3V 供电**，且编码器本身兼容 3.3V，
  A/B 相输出 3.3V —— 接 PA0/PA1 是安全的。
- ⚠ 以后换编码器时注意不要换成只能 5V 供电的型号；真要用 5V 的，
  必须加分压/电平转换，或者把循迹 CH6/CH7 挪走、编码器改到 PA15/PB3。
- `bsp_encoder.c` 里**故意不做** `GPIO_PartialRemap1_TIM2`：
  一旦做重映射，TIM2 通道就跑到 PA15/PB3，PA0/PA1 上的编码器读数恒为 0。

### 2）PA15 / PB3 / PB4 是 JTAG 脚

复位后它们归 JTAG（JTDI / JTDO / NJTRST），不释放就当不了普通 IO，
而且**读不到外部电平且不报错**。

`bsp_encoder.c` 的 `BSP_Encoder_Init()` 里做了
`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`（保留 SWD）。
所以 **`BSP_Encoder_Init()` 必须在 `BSP_Line_Init()` / `BSP_Key_Init()` 之前调用**，
`chassis_task.c` 的初始化顺序已经按这个排好。

### 3）串口只剩 USART1

| 串口 | 引脚 | 状态 |
|---|---|---|
| USART1 | PA9 / PA10 | ✅ 双板链路在用 |
| USART2 | PA2 / PA3 | ❌ 被循迹 CH1/CH2 占用 |
| USART3 | PB10 / PB11 | ❌ 被超声波 Trig/Echo 占用 |

以后要加串口设备（上位机、蓝牙），只能复用 USART1 或用软件串口。

## 5V 电平注意

| 引脚组 | 是否 5V 容忍 | 本工程用途 |
|---|---|---|
| PA0 ~ PA7 | ❌ TTa | 左轮编码器、循迹 CH1/CH2、PWMA/PWMB、AIN1 |
| PB0 / PB1 | ❌ TTa | AIN2 / BIN1（输出，无风险） |
| PA8 ~ PA15 | ✅ FT | 循迹 CH3~CH6、USART1 |
| PB2 ~ PB15 | ✅ FT | 编码器 E2、OLED、超声波、按键、BIN2、STBY |
| PC13 ~ PC15 | ⚠️ 备份域 | 目前全空闲（3 mA / 2 MHz，别驱动 LED） |

- **红外循迹（7 路）**：CH1/CH2/CH5 是 TTa（PA2/PA3/PA12 中前两个是 TTa，
  PA12 是 FT），CH3/CH4 是 FT，CH6/CH7 是 FT。
  整块模块只有一种供电，所以**统一用 3.3V 给红外模块供电**，TTa 脚才安全；
  若只能用 5V，必须加分压电阻或电平转换。
- **H 桥方向脚**：都是 MCU 输出到 H 桥逻辑输入（3.3V 高电平即可被识别），无风险。
- **超声波 Echo**：5V 输出，接 PB11（FT），可直接接。

## 电机 6 线接法

| 电机线序 | 接到 | 说明 |
|---|---|---|
| 1 电机线一 | H 桥 输出 A | 与 6 是电机两端，**不分正负** |
| 2 编码器电源 | **3.3V（左轮）/ 5V（右轮可）** | 左轮编码器在 PA0/PA1，必须 3.3V |
| 3 编码器 A 相 | 左轮 PA0 / 右轮 PB6 | |
| 4 编码器 B 相 | 左轮 PA1 / 右轮 PB7 | |
| 5 编码器地线 | GND | 必须与 MCU 共地 |
| 6 电机线+ | H 桥 输出 B | |

> A/B 相**接反只会让计数方向相反**，不影响安全；如果发现「车往前但计数为负」，
> 交换 A/B 两线即可。
>
> 若「指令正转、车却倒转」，交换 AIN1/AIN2（或 BIN1/BIN2）两根线，或在
> `chassis_config.h` 里把对应侧的 `CHASSIS_MOTOR_*_INVERT` 置 1。

## 三个按键

### 按键（PB12 / PB13 / PB4）

| PCB 位置 | 引脚 | 语义名 | 当前功能 |
|---|---|---|---|
| 中 | PB13 | `BOARD_KEY_MODE` | 切换模式 1 / 模式 2 |
| 左 | PB12 | `BOARD_KEY_START` | 预留（启动 / 暂停） |
| 右 | PB4 | `BOARD_KEY_STOP` | 预留（停车） |

- 三个键都是**上拉输入、低电平有效**（`GPIO_Mode_IPU`），按键另一端接 GND，
  不需要外部上拉。
- 只有 MODE 键接了业务逻辑（`chassis_task.c` 的 `ChassisTask_PollKey`）。
- **PB4 是 JTAG 的 NJTRST**，靠 `BSP_Encoder_Init()` 关 JTAG 后才是普通 IO。
- 想改「哪个键干什么」，改 `pin_config.h` 里三条宏的名字即可，引脚号不用动。

## 超声波（HC-SR04）接线

| HC-SR04 | 接到 | 说明 |
|---|---|---|
| VCC | **5V** | 模块要 5V 才稳定，3.3V 供电测距会明显偏差 |
| GND | GND | 必须与主控共地 |
| Trig | **PB10** | MCU 3.3V 推挽输出，10 µs 触发脉冲；若模块不触发，给 Trig 加 5V 上拉或电平转换 |
| Echo | **PB11** | **模块输出 5V**；PB11 是 FT 脚，可直接接，**不用分压** |

### 为什么选 PB10 / PB11

PB10/PB11 原来是 MPU6050 的软件 I2C 脚（SCL/SDA）。本工程不再使用 MPU6050，
其引脚宏（`BOARD_IMU_*`）已从 `config/pin_config.h` 删除；这两个脚正好空出来给超声波，
不必再占别的引脚 —— PWM、编码器和 7 路循迹已经把其余可用脚占满。
原超声波用的两个脚也已释放为空闲（见「空闲 / 保留」）。

- **Trig 用 PB10**：普通推挽输出即可。PB10 同时是 USART3_TX，
  所以本工程的 USART3 仍然不可用。
- **Echo 必须 FT**（模块输出 5V）：PB11 是 FT，可直接接。
- Echo 接 PB11 → EXTI 线 11 → 仍落在 `EXTI15_10_IRQn`，
  与 `board_config.h` 的 `BOARD_ULTRASONIC_ECHO_IRQn` 一致。
  **若把 Echo 改到 0~4 / 5~9 号线，必须手动把中断号改成 `EXTI0_IRQn`~`EXTI4_IRQn` /
  `EXTI9_5_IRQn`** —— 预处理器没法对 `PIN_INDEX()` 的结果做 `#if`。

### 用 EXTI 而不是硬件捕获

本板没有空闲的定时器捕获通道：TIM2/TIM4 归编码器、TIM3 出 PWM、
TIM1 的捕获脚 PA8~PA11 已被循迹 CH3~CH5 占用。

所以测量方式改成 **EXTI 线 11 双边沿中断 + TIM1 自由运行 1 MHz 时基**：
TIM1 只当计时器用，不接任何引脚。用 GPIO 轮询同样不行 ——
控制环 5 ms 一轮，1 ms 误差折合 17 cm。

> ⚠️ Trig 3.3V 直接驱动 5V 供电的 HC-SR04，可能低于其 VIH（约 3.5V）。
> 若上电后一直测不到距离，先给 Trig 加 1 kΩ 上拉到 5V（或串电平转换）。

## 空闲 / 保留

| 引脚 | 说明 |
|---|---|
| PC13 | 空闲（备份域，可做输入或低驱动输出） |
| PC14 | 空闲（同上） |
| PC15 | 空闲（同上） |
| PA13 / PA14 | **SWDIO / SWCLK，调试口，不要占用** |
| PB2 | BOOT1，上电时不要被外部拉高 |
| PA4 | 空闲（原超声波 Trig，换到 PB10 后让出） |
| PB15 | 空闲（原超声波 Echo，换到 PB11 后让出） |

> 想做第四个按键、蜂鸣器、LED，优先用 PC13~PC15。
> 注意 PC13~PC15 只能在备份域规格内使用（3 mA / 2 MHz），别直接驱动大电流负载。

## 硬件注意

| 项目 | 说明 |
|---|---|
| 电机电源 | H 桥 VM 与 MCU 3.3V **分开供电**，共地；电机启停会打电源冲击 |
| 共地 | 两块主控板、电机电源、传感器、编码器必须共地 |
| 首次上电 | 直流电源限流 1 A，先架起车体（轮子离地） |
| STBY | 电机不转先量 PB5 是否为高 |

## 与云台板的接线

| 云台板 | 方向 | 循迹板 |
|---|---|---|
| PA9（USART1_TX） | → | PA10（USART1_RX） |

云台板只发不收，PA10 那一侧可留空；建议接上以便以后加双向。
