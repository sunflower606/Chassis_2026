## 一、整体设计

### 1.1 本板要解决什么

《实验室学习项目》要求一台带云台的双模式小车，但**实物是两块主控**：

| 板 | 负责 | 工程 |
|---|---|---|
| 云台主控 | K230 视觉识别 + 二自由度舵机云台 | `Gimbal_2026` |
| 循迹主控 | 红外循迹 + 双电机驱动 + 模式切换 + 双板通信 | `Chassis_2026`（本板） |

拆板的好处：云台控制环（10 ms）与底盘控制环（5 ms）互不抢占 CPU，
视觉串口中断也不会打断电机 PWM 的更新节奏。

### 1.2 硬件事实（已确认）

| 项目 | 内容 |
|---|---|
| 电机 | MG513 系列**霍尔编码器款**（MG513X / MG513XL 接口相同） |
| 电机线序 | 1=电机线一、2=编码器电源、3=编码器 A 相、4=编码器 B 相、5=编码器地线、6=电机线+ |
| 底盘 | **后双轮差速驱动**（后轴两驱动轮 + 前部万向轮） |
| 测距 | HC-SR04 超声波（Trig = PB10，Echo = PB11 / EXTI 线 11） |

编码器的存在让后续做轮速闭环成为可能；**当前只用做诊断**（见 3.2）。

### 1.3 两种工作模式

| 模式 | 需求原文 | 本板实现状态 |
|---|---|---|
| 模式 1 循迹 + 云台跟踪 | 小车沿黑线行驶，云台独立盯着人 | 骨架就绪，**判线与转向律留空** |
| 模式 2 纯人体跟随 | 无黑线约束，整车跟随人体目标，保持距离 | **已实现**（云台偏角转向 + 超声距离控前后） |

模式 2 的两路输入是**互相独立**的：

| 通道 | 输入 | 决定 |
|---|---|---|
| 转向 | 云台板发来的 yaw 偏角 | 往哪边拐 |
| 前后 | 本板超声波测距 | 前进 / 后退 / 不动 |

### 1.4 代码分层

```
application/chassis_task.c     ← 模式状态机、按键、显示、分派
        ↓

modules/motor_driver.c         ← 限幅 + 斜率限制 + 输出
modules/vision_link.c          ← 解析云台板发来的 yaw 偏角
modules/distance_sensor.c      ← 超声回波 → 厘米 + 量程/超时判定
modules/oled.c                 ← 显示
        ↓

bsp/bsp_motor_pwm.c            ← TIM3 PWM + H 桥方向
bsp/bsp_encoder.c              ← TIM2 / TIM4 硬件编码器
```

## 二、数据流

### 模式 1（循迹）—— 判线留空

```
7 路红外对管 → BSP_Line_ReadRaw() → 位图（bit0=CH1…bit6=CH7）
   ↓
LineSensor_Update()  → 极性转换 + 加权 + 脱线判定    ← ❌ 待实现
   ↓
ChassisTask_UpdateLineTrack()  → 差速                    ← ❌ 待实现（当前保持停车）
   ↓
Motor_SetSpeed()
```

### 模式 2（跟随）—— 已实现

```
【转向通道】
云台板 ──UART1 13B/30ms──> BSP_UART 环形缓冲
   ↓
VisionLink_Poll()  → 解析 yaw_dev_tenth_deg + flags + 超时判定
   ↓
偏角去死区 → 转向量 steer

【前后通道】
HC-SR04 ──Echo──> PB11(EXTI 线 11 双边沿) + TIM1 1MHz 时基 → 回波脉宽(us)
   ↓
DistanceSensor_Poll()  → us/58 = cm，量程 + 40cm 野值门限 + 5 点中值（60 ms 一次），
                          丢帧保持 1500 ms 后才报无效
   ↓
距离去死区 → 误差 × 增益 → 前后量 speed

【合成】
left  = speed - steer
right = speed + steer
   ↓
Motor_SetSpeed()（参数 = 目标速度）
   ↓
speed_loop：编码器实测速度 → PI（20 ms 一次）→ 占空比
   ↓
限幅 → 斜率限制 → BSP_Motor
   → TIM3(PWMA/PWMB) + AIN1/AIN2/BIN1/BIN2
```

两条通道完全独立：**转向只管朝向，前后只管距离**。
所以「人在侧前方」时会一边拐过去一边保持车距。

### 模式 2 的转向依据（重点）

转向用的是**云台 yaw 偏角**，不是画面偏差。原因：

> 云台一直在跟踪人，人始终被保持在画面中心，**画面偏差恒接近 0**，
> 不携带方向信息。而「云台转了多少度才对准人」正好编码了人相对车头的方位。

```
偏角 -> 去死区 -> 转向量 -> 左右轮差速
```

这构成一个负反馈外环：

```
人偏移 → 云台转 → yaw 偏角 → 底盘转向 → 人相对车头回正 → 偏角减小 → 0
```

因为外环由云台角度闭合，**电机开环占空比也能收敛**；
两轮摩擦力差异造成的直线跑偏由这个外环纠正。
要明显改善直线质量，需要再加一层轮速闭环（编码器已就绪）。

### 模式 2 的前后依据

超声波测「车到人」的距离，与 `CHASSIS_FOLLOW_TARGET_DISTANCE_CM` 比较：

| 情况 | 输出 |
|---|---|
| 距离 > 目标 + 死区 | 正向前进 |
| 距离 < 目标 − 死区 | 负向后退 |
| 在死区内 | 前后量为 0（只转向） |
| 距离无效（超时 / 超量程） | **不前进，只原地比例转向对准**：按偏角大小算转速（越近越慢，抵消链路延时造成的过冲），偏角落进 ±8° 停住；不盲目前冲 |

### 时间尺度

| 环节 | 周期 |
|---|---|
| 底盘控制环 | **5 ms** |
| 云台板发帧 | 30 ms |
| 超声波测量 | 60 ms（HC-SR04 硬性要求） |
| 链路超时 | 500 ms |
| 刷 OLED / 串口回传 | 100 ms / 500 ms |

底盘环（5 ms）比数据源（30 ms）快 6 倍 —— 所以同一个偏角值会被连续用 6 拍，
这是正常的，转向量本身变化很慢，不需要额外滤波。

## 三、各子系统实现

### 3.1 `bsp/bsp_motor_pwm.c` — TB6612 电机驱动

- 模块丝印：`PWMA AIN1 AIN2 STBY BIN1 BIN2 PWMB`，A 通道带左轮、B 通道带右轮。
- TIM3：72 MHz / 72 = 1 MHz，ARR = 1000 → **1 kHz 载波**；PWMA = CH1(PA6)、PWMB = CH2(PA7)。
- 占空比用**千分比**（0~1000）。
- 接口是**带符号速度**：`+1000` 正转、`0` 滑行、`-1000` 反转。
- 真值表（单通道）：`IN1=1,IN2=0` 正转；`IN1=0,IN2=1` 反转；`00` 滑行；`11` 刹车。
  本实现只用前三种，`0` 时两方向脚**同为低**（H 桥关断 = 滑行），不是短路制动。
- **STBY 必须为高**，否则整片芯片待机、PWM 给多少都不转。BSP 在 `Init` 里
  把它配成推挽输出并立即拉高（PB5）。这是接 TB6612 最容易漏的一根线。
- 限幅在 BSP 里再做一次（防御性冗余）。

### 3.2 `bsp/bsp_encoder.c` — 霍尔编码器

- TIM2（左轮，**默认映射 PA0/PA1，不重映射**）+ TIM4（右轮，PB6/PB7），
  均为 16 位、预分频 0、`TIM_EncoderMode_TI12`（4 倍频）。
- 增量用 `int16` 相减，天然处理 16 位回绕。
- **初始化里做了两件容易忘的事**：
  1. 打开 AFIO 时钟；
  2. `GPIO_Remap_SWJ_JTAGDisable` 关 JTAG（保留 SWD），释放 PA15/PB3/PB4。

  ⚠️ 这里**故意不做** `GPIO_PartialRemap1_TIM2`：左轮编码器就接在 TIM2 默认的
  PA0/PA1 上，一旦重映射，通道会跑到 PA15/PB3，PA0/PA1 的读数**恒为 0 且不报错**。
  少做第 2 步则循迹 CH6/CH7 与按键 STOP 读不到电平（同样不报错，见踩坑 6.3）。

### 3.3 `bsp/bsp_line_gpio.c` — 循迹输入

7 路上拉输入（CH1~CH6 在 GPIOA，CH7 在 GPIOB），.c 里用一张
「端口 + 引脚」表按 CH1→CH7 顺序读，一次调用返回同一时刻的位图。
跨端口对上层透明：上层拿到的始终是 bit0=CH1…bit6=CH7 的连续位图。
本层只给电平，**不知道极性**。

### 3.4 `bsp/bsp_key.c` — 模式切换键

上拉输入、低电平有效，只返回原始按下状态，消抖在应用层。

### 3.5 `modules/motor_driver.c` — 差速输出（已启用）

四层处理：

1. **轮速闭环**（P1，2026-11-14 起）：参数是**目标速度**，交给 `speed_loop` 用编码器做 PI，
   输出占空比；`CHASSIS_SPEED_LOOP_ENABLE=0` 时退回开环（参数直接当占空比）；
2. **目标限幅**到 `±CHASSIS_MOTOR_DUTY_MAX`（当前 700‰，留 30% 余量）；
3. **斜率限制**：每调用一次朝目标最多走 `CHASSIS_MOTOR_RAMP_PER_TICK`（40‰）；
4. **输出**到 BSP。

目标值与输出值分开保存 —— 这样「要求急停」和「实际缓停」可以同时存在：
`Motor_SetSpeed(0,0)` 给的是目标，实际输出会在若干拍内降到 0，这就是「减速停止」的实现方式。

`Motor_Stop()` 是安全路径，**不走斜率**，直接清零并关断 H 桥，同时 `SpeedLoop_Reset()`
清积分并丢弃停车期间攒下的编码器增量（否则起步第一拍会读到巨大假速度而反向踢一下）。

#### 3.5.1 `modules/speed_loop.c` — 轮速闭环（P1）

**为什么要有**：占空比 ≠ 速度。同样 350‰，满电和亏电、地砖和地毯，实际车速能差一倍，
开环时「参数调准」是不可能的，因为被控对象一直在漂。

**算法**（每 4 拍 = 20 ms 算一次，其余拍保持输出）：

```c
meas  = 编码器增量 × SIGN × SPEED_PER_COUNT        // ‰，正 = 后退
err   = target - meas
integ += KI × err × 0.02s                          // 夹到 ±INTEG_MAX
duty  = target + KP × err + integ                  // 前馈 + 比例 + 积分
duty  = clamp(duty, ±DUTY_MAX)                     // 饱和时撤掉同向积分（抗饱和）
duty  = sign(duty) × MIN_DUTY  （若有目标且 |duty| < MIN_DUTY）  // 静摩擦补偿
```

- **前馈取 target 本身**：按标定，稳态「speed ‰」≈「duty ‰」，所以一开始就给接近正确
  的占空比，PI 只修残差（KI 很小也不会「起步半天不动」）。
- **为什么 20 ms 算一次**：5 ms 内编码器只走十几个计数，1 个计数 ≈ 几十‰ 速度，
  5 ms 算一次 PI 会跟着量化噪声抖；攒 4 拍分辨率提高 4 倍。
- **静摩擦补偿**：占空比太小电机压根不转，PI 会误以为「还没动」把积分顶满，
  所以有目标就至少给 `CHASSIS_SPEED_MIN_DUTY`（70‰）。
- **符号**：`CHASSIS_SPEED_SIGN_LEFT=-1`、`CHASSIS_SPEED_SIGN_RIGHT=+1`
  （实机：左轮前进计数为正、右轮前进为负，而速度约定正 = 后退），见问题记录 C-04。
- **可观测**：串口 `sp=` 是实测速度、`out=` 是占空比。上坡/地毯/亏电时 `out` 自己变大而
  `sp` 保持 —— 这就是闭环在起作用。

### 3.6 `modules/line_sensor.c` — 判线（留空）

当前只取原始电平，`position` 恒 0、`lost` 恒 1。

`lost = 1` 是刻意选的「不知道」值，让人一眼看出判线还没实现，
而不是让它看起来像「线在正中」。

### 3.7 `modules/vision_link.c` — 双板链路（已实现）

- 13 字节帧，`type = 0x02`，与 K230 帧同结构（只有 type 不同）。
- 解析器与 K230 解析器同一套策略：滑窗找帧头、失配只前进 1 字节、
  校验失败只丢 1 字节重同步、没找到帧头时保留末尾 3 字节。
- `fresh` 的判定要同时满足：`flags.bit0 = 1`（有人）**且** 未超时 ——
  两者缺一不可，否则会把「没人」或「断线」当成有效数据继续转向。

### 3.9 `bsp/bsp_ultrasonic.c` — HC-SR04 驱动

- Trig = PB10（推挽输出），Echo = PB11（EXTI 线 11 双边沿中断）。
- 为什么用 EXTI 而不是硬件捕获：本板没有空闲的捕获通道（TIM2/TIM4 归编码器、
  TIM3 出 PWM、TIM1 的捕获脚 PA8~PA11 已被循迹 CH3~CH5 占用），
  所以用 **EXTI + 自由运行时基**：
  - TIM1 配成 **1 MHz** 自由运行、不接任何引脚；每 65536 us 溢出一次，
    溢出中断里累加 32 位时基高位；
  - EXTI 线 11 上升沿：记下回波起点，把触发条件切成下降沿；
  - 下降沿：算 `width = now - rise`，置「有新数据」，再切回上升沿。
- 时基读取用「读两次高位、不一致就重读」，避免 16 位计数器与高位撕裂。
- `BSP_Ultrasonic_ResetEcho()` 专门用于超时复位：只捕到上升沿时触发边沿会停在
  下降沿，不复位的话下一次测量永远接不上（表现为「从此再也没有距离」）。
- 本工程 Drivers 里**没有 `stm32f10x_exti.c`**（只有 .h），
  所以 EXTI 配置（AFIO->EXTICR、EXTI->IMR/RTSR/FTSR/PR）在 BSP 里直接写寄存器。

### 3.10 `modules/distance_sensor.c` — 距离换算与有效性

- 换算：`cm = echo_us / 58`（声速 340 m/s，往返双程；1 cm ≈ 58 us）。
- 每 **60 ms** 触发一次 —— HC-SR04 的硬性要求，间隔更短时上一次的余波会被
  当成这一次的回波，读数会突然变小（看起来像「人突然变近」）。
- **三级筛选（2026-11-14 新增，治「走两步停一下」）**：
  1. 量程：换算结果不在 `[MIN_CM, MAX_CM]`（2~400 cm）→ 丢弃（盲区或超范围）；
  2. 野值门限：与上一条被接受的读数差 > `CHASSIS_DISTANCE_JUMP_CM`（40 cm）→ 丢弃；
     连续被拒 `CHASSIS_DISTANCE_JUMP_FORCE`（3）次则认定目标真跳变，清空历史强制接受；
  3. 中值：最近 `CHASSIS_DISTANCE_MEDIAN_WINDOW`（5）条被接受的读数取中值。
- **短时保持**：回波超时（50 ms 内没有下降沿）只让本次作废，**不清空已保持的值**；
  超过 `CHASSIS_DISTANCE_HOLD_MS`（1500 ms）没有新采样，才对外报无效。
- 标志语义：`valid` = **可以参与控制**（新鲜值或保持中的值），`fresh` = 最近
  `CHASSIS_DISTANCE_FRESH_MS`（150 ms）内有新采样，`age_ms` = 距上次被接受采样的毫秒数。
  上层若要看「真的丢了多久」，必须用 `GetAgeMs()` / `IsFresh()`，不能用 `IsValid()`。
- **已知缺口**：近距急停（<25 cm）同样用 `valid`，保持期内按旧值判断，
  对着墙丢回波时会迟钝 1.5 s（待改成直接读原始回波）。
- 为什么不上卡尔曼：HC-SR04 是单点、60 ms、易丢，数据率太低；中值 + 保持
  已经能吃掉绝大部分「丢一帧就停」的抖动，而且行为可解释、可手算。

### 3.11 `application/chassis_task.c` — 模式状态机

```
上电 → CHASSIS_MODE_LINE_TRACK（电机滑行）
          │  按下模式键（消抖 20 ms，只在下沿翻转）
          ├──────────────► CHASSIS_MODE_FOLLOW
          ◄──────────────┤
```

要点：

- 只在下沿切换，长按不重复切；
- 切模式瞬间 `Motor_Stop()`，避免带着上个模式的输出冲出去；
- `switch` 的 `default` 强制回安全态；
- 上电默认电机滑行。

模式 2 的执行顺序（`ChassisTask_UpdateFollow`）：

1. 人丢了 / 链路断 → 停车返回；
2. 算转向量 `steer`（偏角 → 死区 → 增益 → 符号 → 限幅）；
3. 算前后量 `speed`（距离 → 死区 → 增益 → 限幅）；
   距离无效时按 `CHASSIS_FOLLOW_REQUIRE_DISTANCE` 决定「只按偏角比例转向对准」还是定速前进；
4. 合成 `left = speed - steer`、`right = speed + steer`（本车「正=后退」，
   故左减右加；写成左加右减会让车朝反方向转），各自夹到硬件限幅；
5. 交给 `Motor_SetSpeed`（内部斜率限制后输出）。

### 3.12 OLED 布局

```
Mode:FOLL OK
Dev: +30
Dist:102cm
L:+287 R:+213
```

- 第 1 行：模式 + 链路状态（`OK` / `--`）
- 第 2 行：模式 1 显示 7 路电平位图（Raw:0000000，CH1 在左、CH7 在右）；
  模式 2 显示云台 yaw 偏角（整度）
- 第 3 行：超声波距离（无效时显示 `Dist:---cm`）
- 第 4 行：左右轮**实际输出**（不是目标值）

第 1~3 行采用「补齐 16 列整行重写」，避免切换模式时残留旧字符。

## 四、关键参数与来源

电机与跟随参数（`CHASSIS_MOTOR_*`、`CHASSIS_FOLLOW_*`）现在集中定义在

### 转向符号的判定（不要靠直觉）

摄像头装在云台上，视角与车头相反，靠「哪边轮子该快」的直觉很容易推反。

**唯一可靠的判据**：架起车体（轮子离地），把人放到画面偏一侧，看轮子往哪边快；
然后落地看**车是否朝人的方向转**。方向反了就改 `CHASSIS_FOLLOW_STEER_SIGN`。

## 五、安全层

| 场景 | 当前行为 | 位置 |
|---|---|---|
| **上电瞬间** | 电机滑行（H 桥关断，占空比 0） | `BSP_Motor_Init` 末尾 |
| **上电默认模式** | 模式 1（循迹），而模式 1 逻辑留空 → 保持停车 | `chassis_task.c` |
| **模式切换瞬间** | 先 `Motor_Stop()`（不等斜率）再切 | `chassis_task.c` |
| **模式变量异常** | `switch` default 回安全态 + 停车 | `chassis_task.c` |
| **目标丢失（模式 2）** | 立即下发 0 目标 → 斜率减速到停 | `chassis_task.c` |
| **链路断线（模式 2）** | 500 ms 超时 → 同上 | `vision_link.c` |
| **距离无效（超声超时 / 超量程）** | 不前进，只按偏角比例原地转向对准（越近越慢，±8° 内停住，12° 外才重新转） | `chassis_task.c` |
| **占空比越界** | Module 与 BSP 双层限幅 | 两处 |
| **起步电流冲击** | 斜率限制（50‰/拍） | `motor_driver.c` |
| **看门狗** | ❌ 未启用 | 见优化空间 |

**上电默认状态**：模式 = 循迹，电机 = 滑行。车不动。

**zero force / safe mode**：`Motor_Stop()` 就是硬件层面的零力输出（H 桥关断），
任何安全路径都可以直接调它。

## 六、踩过的坑

### 6.1 用画面偏差做转向，车永远不会动

**现象（设计阶段发现，未上实车）**：把 K230 的画面偏差发给底盘做转向，
底盘收到的值恒接近 0，车不转。

**根因**：摄像头装在云台上，而云台一直在跟踪人 ——
人被人为保持在画面中心，画面偏差就是控制器的**残差**，本来就该接近 0。

**修复**：改发**云台 yaw 偏角**。偏角 > 0 表示云台转过去对准人，
即人在车头那一侧的某个方位；车转向该方位后偏角自然归零。

**以后如何避免**：闭环系统里「残差」不能当外环的输入信号，
要找那个**尚未被内环消掉**的量（这里是云台角度）。

### 6.2 编码器接在 TTa 脚（PA0/PA1）上的 5V 风险

**现象（本板实际的引脚约束）**：左轮编码器 A/B 接在 TIM2 默认的 **PA0/PA1**。

**根因**：PA0~PA7 是 `TTa`（非 5V 容忍）。若霍尔编码器用 **5V 供电**，
A/B 相输出就是 5V，超过引脚绝对最大额定值，长期会损伤 MCU。
右轮用 TIM4 的 **PB6/PB7**（`FT`），没有这个问题。

**当前处理（已确认）**：左轮编码器由 **3.3V 供电**，编码器本身兼容 3.3V，
A/B 相输出 3.3V —— 接 PA0/PA1 安全（见 docs/引脚分配.md）。

**如果只能 5V**：① 给 A/B 相加分压/电平转换；或 ② 把循迹 CH6/CH7 从 PA15/PB3
挪走，编码器改到 PA15/PB3（`FT`，需在 `bsp_encoder.c` 里恢复
`GPIO_PartialRemap1_TIM2`）。

**以后如何避免**：任何外部 5V 信号进 MCU 前，先查数据手册该脚的 FT / TTa 属性。

### 6.3 JTAG 脚没释放，读数恒为 0 而且不报错

**现象**：循迹 CH6/CH7（PA15/PB3）或按键 STOP（PB4）读数一直是固定值。

**根因**：PA15/PB3/PB4 复位后是 JTAG 引脚（JTDI/JTDO/NJTRST），
不关 JTAG 的话这几个脚不能当普通 IO / 定时器输入用。**编译器和外设库都不会报错。**

**修复**：`bsp_encoder.c` 的 `BSP_Encoder_Init()` 里
`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`（保留 SWD），
并且**该 Init 必须在 `BSP_Line_Init()` / `BSP_Key_Init()` 之前调用**。

**以后如何避免**：用 PA15/PB3/PB4 做外设功能时，第一件事就是关 JTAG。

### 6.4 引脚表写重，两个功能抢同一个脚

**现象**：手写 `board_config.h` 时循迹 CH1 与 CH5 都写成 `PA0`。

**根因**：靠记忆逐条写引脚，没有做总览对账。宏展开合法，编译器不会报错。

**修复**：把引脚表改成「文件头总览注释 + 宏」两处对应，逐条核对。

**以后如何避免**：新增/修改引脚时先看图，再写宏。

### 6.5 超声波回波只捕到上升沿，之后再也没有距离

**现象**：前几次测距正常，某次「人走远了/前面空了」之后，
`Dist` 一直显示 `---`，再也不恢复。

**根因**：捕获状态机是两沿的。只捕到上升沿时，极性停在「等下降沿」，
而回波根本没来，于是永远等不到 —— 下一次测量完全接不上。
这是**状态机卡死**，不是模块坏。

**修复**：`DistanceSensor_Poll` 里等回波超时后调
`BSP_Ultrasonic_ResetEcho()`，强制把极性和状态复位到「等上升沿」。

**以后如何避免**：任何「等第二个事件才完成」的状态机，
都必须有一个**超时复位**路径，否则一次丢失事件就能让它永久卡死。

### 6.6 超声波触发太快，距离会突然变小

**现象**：把测量周期从 60 ms 改小后，静止目标偶尔显示的距离突然掉一半。

**根因**：HC-SR04 每次测完会有一段余波在空气里衰减。间隔太短就再触发时，
模块可能把**上一次的余波**当成这一次的回波，测出来是「更近的距离」。

**修复**：固定 60 ms 周期（`CHASSIS_ULTRASONIC_PERIOD_MS`），不要为了「更实时」调小。

**以后如何避免**：这类传感器手册上的最小测量间隔是硬约束，
不是「建议值」，别按直觉压缩。

## 七、优化空间

### 7.1 待实现（按建议顺序）

1. **电机方向与转向符号实测**（必须最先做）；
2. **超声距离闭环整定**：目标车距、死区、增益、前后限速；
3. **编码器分辨率标定** + 轮速计算；
4. **轮速闭环**（编码器 PID）：解决两轮摩擦力不同导致的直线跑偏，
   这是当前模式 2 最值得做的一项优化；
5. **循迹判线 + 模式 1 控制律**；
6. **双板反向通道**：云台板加 USART1 接收，循迹板发模式/急停。

> 距离闭环本身**已实现**（不再是待办项）。剩下的只是把参数整定到好用。

### 7.2 有价值但暂不建议做

| 项目 | 原因 |
|---|---|
| PID 循迹 | 先用 P 跑通；5 个离散红外量做积分意义不大 |
| 加速度前馈 | 底盘动力学还没建模，先有速度闭环再谈 |
| 视觉直接控底盘（不经云台） | 云台已提供高质量方位信号，没必要多一条路径 |

### 7.3 优化前需要的测试条件

- 可架起车体的台架（测轮子转向、编码器必须离地）
- 一段画好的黑线赛道（含直道 + 直角弯 + 圆弧弯）
- 直流电源带限流（首次上电限 1 A）
- 云台板已能稳定跟踪人（模式 2 依赖它）

## 八、必须遵守的设计规范

1. `application/` 禁止直接调用 `GPIO_*` / `TIM_*` / `USART_*`；
2. 所有速度量用 `_per_mille` 后缀标明千分比；偏角用 `_tenth_deg` 标明 0.1 度；
3. 禁止魔法值，参数集中到 `config/motor_pid_config.h`（电机/跟随）与
   `config/chassis_config.h`（其余）；
4. **电机输出必须限幅**：Module 与 BSP 两层都要夹；
5. 任何驱动电机的改动都必须保留「上电滑行」这一行为；
6. 模式切换必须先停车再切；
7. 未实现的接口必须能表达「未实现」，不得返回伪正常值；
8. 改双板协议必须同时改两侧代码 + `docs/双板分工与协议.md` + 跑配对测试；
9. 修改公共接口、控制参数、安全逻辑后必须同步更新本文档。
